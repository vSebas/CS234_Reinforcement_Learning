\section{Limitations}

This project has several limitations that materially affect interpretation.

\begin{itemize}
\item Many final downstream comparisons are small smoke benchmarks, especially the final post-fix failure-conditioned rerun with only 3 scenarios per gate.
\item Most completed controlled evaluations are IPOPT diagnostics, not full FATROP deployment benchmarks, even though FATROP-clean data generation was the active dataset pipeline.
\item Acceptance depends on a hand-designed threshold gate, and some projection metrics are aggregate wrapper diagnostics rather than physically clean control-theoretic quantities.
\item The evaluation output's \texttt{lap\_time} field corresponds to optimizer objective value rather than pure terminal time, so it should not be over-interpreted.
\item The final failure-conditioned shard contains only 300 accepted segments, which is enough for a targeted fine-tune but still small relative to the shift shard.
\end{itemize}

Because of these limitations, the strongest safe conclusion is not that DT warm-starting fails in general, but that the implemented system in this repo did not yet produce a convincing solver-facing win on the final corrected benchmarks.
